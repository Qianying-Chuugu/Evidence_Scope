## 三、EvidenceScope 项目定位

项目名称：**EvidenceScope**

项目方向：基于 LLM Agent 与 RAG 的中文企业及行业研究系统。

### 1. 项目要解决的问题

传统大模型在分析企业财务状况和行业趋势时，可能存在：

- 对企业最新信息掌握不完整
- 财务数据引用不准确
- 无法追溯分析结论的原始来源
- 跨文档综合分析能力不足
- 生成没有充分证据支撑的结论

EvidenceScope 希望通过 Agent、RAG 和证据核验机制改善这些问题。

### 2. 最终期望具备的能力

用户可以：

- 上传企业年报、行业报告等 PDF 文件。
- 使用自然语言查询企业财务信息。
- 对比不同年份的经营数据。
- 发起企业或行业研究任务。
- 查看系统引用的原始证据、文档名称和页码。
- 获取有证据支撑的分析报告。

系统应逐步具备：

- PDF 解析与知识库建立
- BM25 + Embedding 混合检索
- Reranker 精排
- Agent 自主调用检索与计算工具
- 财务数据的确定性计算
- 证据来源追踪与核验
- 多步骤研究任务编排
- FastAPI 后端服务
- Web 图形化界面
- 检索及回答效果评测

初期使用**宁德时代 2025 年年度报告**作为真实测试数据。

以后可以扩展到多家企业、多年度报告以及行业研究资料。

## 四、项目目前的实际进度

项目使用 Python 开发，目前主要在 Windows 本地虚拟环境中运行。

已实现的模块如下。

### 1. 基础 Agent

`main.py`

- 作为命令行启动入口，读取配置并组装 Agent。
- 通过 OpenAI 兼容接口调用 DeepSeek。

`agent/harness.py`

- 实现通用 Agent Loop、消息历史、工具调用、异常处理和最大迭代次数控制。
- 不直接依赖具体检索算法或财务业务规则。

`agent/tool_registry.py`

- 集中保存工具 Schema 和工具名称到 Python 函数的映射。
- Harness 通过注册表调用工具，不直接依赖工具实现。

`skills/local_document_qa.py`

- 保存本地商业文档问答的系统提示词。
- 定义查询构造、补充检索、证据核验、引用格式和拒绝编造规则。
- 后续新增研究工作流时，可以继续添加独立 Skill，而不修改 Harness。

### 2. 早期财务计算工具（已移除）

项目早期曾使用 `tools/finance.py` 和 `data/financial_facts.json` 保存单家公司、单个指标的人工整理数据，并计算营业收入同比增长率。

为了聚焦通用 RAG 检索与评测流程，避免继续维护硬编码数据，该功能现阶段已从代码中移除。以后如需恢复确定性财务计算，应基于“检索证据、结构化提取、证据核验、Python 计算”的通用流程重新实现。

### 3. PDF 搜索工具

`tools/pdf_search.py`

- 使用 PyMuPDF 读取 PDF。
- 根据关键词查找相关原文。
- 返回匹配内容及 PDF 页码。

这是早期的字符串搜索版本，目前保留用于对照，但已不再作为 Agent 的默认工具。

### 3.1 Agent RAG 检索工具

`tools/evidence_search.py`

- 对外提供 `search_evidence(query, top_k)`。
- 内部依次执行 BM25、Dense、加权 RRF Hybrid 和 Reranker。
- 默认从 Hybrid Top-20 候选中重排并返回 Top-5 证据。
- 返回原文、PDF 页码、Chunk ID 以及各检索阶段排名。
- 检索模型在第一次调用时加载，之后的 Agent 工具调用复用同一组对象。
- `main.py` 已要求 Agent 在回答本地文件事实前调用该工具，证据不足时可以改写查询再次检索，最终答案必须引用文件名、页码和 Chunk ID。

### 4. PDF Chunking

`retrieval/chunking.py`

- 使用 PyMuPDF 解析本地 PDF。
- 扫描 `data/documents/` 下的多个 PDF，并兼容原有 `data/CATL_2025.pdf`。
- 当前采用基于字符数和重叠区域的分块策略。
- 将结果保存到 `data/chunks.json`。
- 每个 Chunk 包含 `chunk_id`、`document_id`、`source`、`source_path`、`page`、`text` 等信息。
- 当前分块大小为 500 个字符，相邻分块重叠 150 个字符。
- 新增文件后运行 `python -m retrieval.chunking` 即可统一重建分块；Dense 会在下一次启动时自动重建向量。

当前仍存在简单字符分块可能破坏财务表格结构的问题，后续可以根据检索结果优化。

### 5. BM25 关键词检索

`retrieval/bm25_search.py`

- 使用 `jieba` 进行中文分词。
- 使用 `rank-bm25` 实现 BM25 检索。
- 已实践自定义专业词汇。
- 能够返回 Top-K Chunk、相关性分数和 PDF 页码。

已经成功找到年报第 24 页的营业收入整体情况，包含：

- 2025 年营业收入：423,701,834 千元
- 2024 年营业收入：362,012,554 千元
- 同比增长：17.04%

### 6. Dense Retrieval 向量检索

`retrieval/dense_search.py`

- 使用 `BAAI/bge-small-zh-v1.5` 中文 Embedding 模型。
- 每个 Chunk 生成 512 维向量。
- 使用 NumPy 保存向量矩阵到 `data/dense_vectors.npy`。
- 查询时将问题编码成向量。
- 通过向量点积计算归一化向量的余弦相似度。
- 按得分返回 Top-K Chunk。

已经成功运行，生成的向量矩阵形状为：

`(1378, 512)`

可以检索到包含营业收入数据的财报片段。

### 7. Hybrid Search

`retrieval/hybrid_search.py`

当前已经实现并通过真实数据测试：

1. BM25 与 Dense 分别召回 Top-N Chunk。
2. 使用 `chunk_id` 识别重复候选。
3. 通过 RRF（Reciprocal Rank Fusion）计算综合排名。
4. 返回融合后的 Top-K 结果。

当前采用加权 RRF，默认权重为 BM25 `1.5`、Dense `1.0`。该权重来自早期小规模开发实验；后续权重比较只能使用开发集，选定方案后再在冻结测试集上验证。

已新增 `retrieval/reranker.py`，使用本地 `BAAI/bge-reranker-base` 对 Hybrid Top-20 候选进行 Cross-Encoder 重排，并在 `retrieval/evaluate_retrieval.py` 中接入 BM25、Dense、Hybrid、Hybrid + Reranker 四路对照。20 题开发集上，Hybrid 的 Hit@5/MRR/Recall@5 为 `0.85/0.5892/0.7812`，重排后为 `0.85/0.5492/0.7375`；10 题冻结测试集上，二者分别为 `0.90/0.6533/0.85` 和 `0.90/0.75/0.90`。重排平均耗时约 `2.6s`，而 Hybrid 约 `15ms`。尽管离线收益尚不稳定，项目当前仍按产品设计将完整 Hybrid + Reranker 链路接入 Agent，后续从 Agent 查询改写、多轮检索和端到端回答质量继续评估。

评测数据已拆分为 `data/retrieval_eval_dev.json`（20 题开发集）和 `data/retrieval_eval_test.json`（10 题冻结测试集）。开发集用于分析错误和调参，测试集只用于选定方案后的最终检查。评测指标包括 Hit@K、MRR、Recall@K 和平均查询耗时。当前数据仍只来自一份年报，尚不能代表跨公司、跨年份的整体性能。
